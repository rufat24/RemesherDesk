# Work breakdown

## How tasks work

**Size.** Each task is sized for **one cloud session**: about 2–4 hours of agent time, with one commit series and one push.

**Each task lists:**
- **Dep:** the tasks it depends on.
- **Files:** what it touches.
- **Do:** the steps.
- **Exit:** the checks that must pass. They are commands a fresh session can run.

**Shared rules for every task:**

- Work on a branch named `task/<ID>-<slug>`, unless the session harness assigns one. Push the branch and open a PR only if the user asks.
- Before pushing, run `cmake --preset ci-gcc && cmake --build --preset ci-gcc && ctest --preset ci-gcc` and the same for `ci-clang`, and get them all green. On a fresh container, run `apt-get install -y libclang-rt-18-dev` first; the ASan link needs it.
- Add a dependency by pinning it in `cmake/Deps.cmake`. Use `FetchContent_Declare` with `URL` plus `URL_HASH SHA256=…`, or `GIT_TAG <full commit sha>`. In the same commit, add a row to the licence table in `docs/packaging-licensing.md`, with the licence read from the actual LICENSE file.
- Each subsystem adds its own `add_subdirectory` line at the top level. Keep the edits to `CMakeLists.txt` at the top level to one line each, so that parallel tasks rarely conflict.
- Update the task's row in §3 (status) and any doc it changes.

### A4 — OBJ import/export

**Dep:** A2. It can run in parallel with A3.

**Files:**
- `src/io/obj.hpp/.cpp`
- `cmake/Deps.cmake` (tinyobjloader pinned)
- `tests/unit/test_obj.cpp`

  - negative indices
  - n-gons
  - `vt`/`vn` per corner
  - no normals
  - CRLF line endings
  - comments
  - `o`/`g`/`usemtl` (→ `face_group`)

**Do:**
- Reader with `triangulate=false`. Split per-corner attributes into unique vertices.
- Writer:
  - `%.9g`
  - `v`, optional `vt`/`vn`, and `f` with 1-based indices
  - `g` per `face_group`
  - always `\n` line endings
- An import convention option.

**Exit:**
- A round trip (write → read) reproduces the positions bit for bit and the faces exactly.
- A 1M-triangle generated OBJ loads in under 3 s in a Release build on the CI runner. Record the timing; it is a target, not a gate.

### A5 — Metrics and comparison

**Dep:** A2.

**Files:**
- `src/core/include/rdesk/metrics.hpp`
- `src/core/src/{metrics.cpp,aabb_tree.cpp,sampling.cpp,pcg32.hpp}`
- `tests/unit/test_metrics.cpp`
- `tests/property/test_properties.cpp`

**Do:**
- **Stats:** V/F, triangle/quad/n-gon counts, quad ratio, valence histogram, irregular vertices (interior valence other than 4, boundary valence other than 3), edge length min/mean/max, quad aspect and angle quality, bounding box.
- **AABB tree** over triangles. Quads are split for distance queries only, using both diagonals: take the minimum distance. Document the bias.
- **Area-uniform sampling** with an in-house PCG32 and a fixed seed. Do not use `std::uniform_*_distribution`, whose output differs between standard libraries.
- **Distances:** one- and two-sided Hausdorff, Chamfer (mean), RMS.
- `compare(ref, test, tier) → CompareReport`, as JSON.

**Exit:**
- Hausdorff of a mesh with itself is 0.
- A cube against the same cube scaled by 1.01 gives Hausdorff ≈ 0.005·side (within 5%).
- Property tests: 200 random meshes, generated by subdivided platonic solids plus a random perturbation, with seed listed in the failure message. They check:
  - metric invariants (symmetry of two-sided Hausdorff)
  - sampling determinism: same seed gives identical samples on all three compilers
